# 004 - 0.3.0 toolchain and Node.js upgrade

- Status: Accepted
- Date: 2026-11-13
- Supersedes: none

## Context

Every dev dependency, the Node.js baseline and the GitHub Actions were
brought to their latest stable versions. Node 26 ("Lithium") is the current
LTS; Node 20 went end-of-life on 2026-04-30.

## Decision

### Node.js baseline

`engines.node` moves from `>=20` to `>=22.18`. That is the lowest version
satisfying every dev tool: `vitest` 5 needs `^22.12`, `tsup` 9 needs
`^22.18`. CI covers 22, 24 and 26; releases are built on 26. The tsup target
moves to `node22`. Because this drops a runtime for consumers, the version
goes to 0.3.0.

### TypeScript stays on 6.0.x

TypeScript 7.0.2 is the latest release, but `typescript-eslint` 8.72.2
declares `typescript <6.1.0`. Forcing TS 7 would need peer-dependency
overrides and would make linting unreliable. We stay on 6.0.x until
`typescript-eslint` supports 7, then upgrade.

### minimatch override

`eslint` 10 and `typescript-eslint` pull in `minimatch` 10.x, which has a
moderate-severity DoS advisory fixed in 11.x. An `overrides` entry pins
`^11.0.8`. It only affects dev tooling, and lint, typecheck, tests, coverage
and package checks all pass with it. Remove it once upstream bumps.

### npm 12

`packageManager` moves to `npm@12.2.2`. npm 12 blocks install scripts that
are not allow-listed; the only one affected is `esbuild`'s postinstall, which
is a verification step, and builds work without it.

## Consequences

- Consumers on Node 20/21 must stay on 0.2.x.
- A follow-up is needed for TypeScript 7 once `typescript-eslint` supports it.
